# 构建与运行

## 构建框架和示例

使用 `go.mod` 声明的 Go 1.27.2。在仓库根目录执行 `go mod download`。只使用框架库时可直接导入所需包；要构建整个仓库，先按[协议示例](../../examples/protocol/README.md)安装固定版本的生成工具，并运行对应平台的 `Generate-Protocol` 脚本。随后执行：

```sh
go build -mod=readonly ./...
```

[回环集群示例](../implementation/cluster-guide.md)给出 NATS、etcd、网关和后端的启动顺序，以及用客户端发送第一条消息的命令。示例使用单独的本机服务，不需要 MySQL。

## 运行游戏模板

模板与框架、配套协议源、表格源使用平级目录。先从同版协议和表格源生成产物，再使用模板的构建脚本编译 gateway、account、game、world 和示例客户端。项目模板还需准备 MySQL 和服务凭据；涉及公共 Boss 的玩法需启动 world。详细命令见模板的 `docs/getting-started.md`。

## 更换服务版本

保持客户端和服务端的消息编号、消息字段及表格版本配套。模板的服务会在启动时按当前 GORM 模型初始化表结构。回退二进制前，检查已有数据和配置能否被目标版本读取。

正常停服使用服务的 `stop` 命令并等进程完成收尾。疑似失联的后端可能仍有在途写入。人工移除业务归属前，先确认旧进程已停、写入风险已处理，再按项目的恢复流程操作。[状态归属边界](10-state-saving.md)
