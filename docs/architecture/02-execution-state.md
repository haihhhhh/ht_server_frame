# 哪些操作需要一起排队

项目按需要共同读写的内存选择处理范围。各玩家主要修改自己的数据时，可以各用一个循环；同一场战斗的多个参与者需要一起结算时，可以把这场战斗交给一个循环。对另一进程的调用仍通过 RPC 发送。

| 场景 | 处理方式 |
| --- | --- |
| 单个玩家使用经验道具 | 模板的玩家循环在一次任务中扣道具、增加经验，并返回本次变化。 |
| 同一公共 Boss 收到多人攻击 | 模板的 world 以 Boss 标识排队处理血量。不同玩家向这个服务发出独立调用。 |
| 无共享状态的请求 | 用 `app.Call` 直接处理，或用 `app.RegisterPool` 分给固定数量的执行通道。 |

使用框架提供的串行队列时，在启动前调用 `app.NewGroup` 创建执行组，再用 `app.RegisterKeyed` 提供从请求得到 key 的函数。只有进入同一实例、同一组、同一 key 的回调会顺序执行。配置队列大小、字节上限和域数上限，满时调用方得到拒绝。[执行器用法](../implementation/execution-guide.md)

执行中的回调可能在请求超时后继续运行。返回响应或提交后台保存时，先在队列内复制需要的值，避免队列外的编码或写库再次读取可变状态。

跨进程业务需要分别处理结果。例如 game 保存玩家的挑战次数，world 保存 Boss 血量；两份保存任务各有结果。发给 world 的攻击超时后不能确定是否已经扣血，请求方不会自动重发。[状态保存与归属](10-state-saving.md)
